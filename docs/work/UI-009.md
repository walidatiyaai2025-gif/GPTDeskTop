# UI-009 — MainForm event/resource lifetime cleanup

Issue: #119

Implementation branch: `agent/ui-009-mainform-event-lifetime`

Status: **IN PROGRESS — implementation and regression coverage complete; CI verification pending**

## Objective

Ensure `MainForm` does not remain retained by long-lived `ChatGptMonitorService` event subscriptions after teardown, and ensure MainForm-owned non-control UI resources are disposed exactly once through the form disposal lifecycle.

## Root cause

`MainForm.WireEvents` previously subscribed to `ChatGptMonitorService.Activity`, `HistoryChanged` and `RunningStateChanged` using anonymous lambdas. Those delegate instances could not be referenced later for matching unsubscription, so the long-lived monitor service could retain the form after teardown or future form recreation.

The MainForm-owned `ToolTip` and cached runtime-status `Font` were also disposed only from the completed `OnFormClosing` path. That did not provide a general component-disposal contract and duplicated resource cleanup responsibility inside shutdown orchestration.

## Implementation contract

1. Monitor service subscriptions use named handlers.
2. `Dispose(bool)` removes the exact three named monitor-service subscriptions before base form disposal.
3. A `_uiResourcesDisposed` guard makes owned resource cleanup idempotent.
4. The MainForm-owned runtime-status font is disposed from `Dispose(bool)`.
5. The MainForm-owned ToolTip is disposed from `Dispose(bool)`.
6. `OnFormClosing` remains responsible only for the bounded graceful-shutdown orchestration and no longer owns those resource disposals.
7. Named handlers preserve the existing Activity, History refresh and Running-state refresh behavior.
8. Existing `Ui(...)` shutdown/disposal guards continue to reject callbacks during teardown.

## Regression coverage

`MainFormResourceLifetimeTests.cs` requires:

- named monitor-service subscriptions with no anonymous monitor event lambdas;
- matching unsubscriptions in `Dispose(bool)`;
- one and only one explicit disposal site for the cached runtime-status font and ToolTip;
- no resource disposal in `OnFormClosing`;
- preservation of the existing activity/history/runtime refresh handler behavior;
- preservation of the UI shutdown/disposal callback guard.

## Compatibility

No monitoring semantics, Start/Stop/Delete lifecycle behavior, Chrome DOM/CDP behavior, recovery, conversation rotation, delivery verification, SQLite schema, configuration import/export, Setup or stable-release publisher behavior is intentionally changed.

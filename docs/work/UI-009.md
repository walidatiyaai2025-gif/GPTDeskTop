# UI-009 — MainForm monitor subscription and owned resource lifecycle

Issue: #119 — **COMPLETED**

Implementation branch: `agent/ui-009-mainform-resource-lifecycle`

Implementation PR: #130

Status: **DONE / VERIFIED / MERGED**

## Objective

Make MainForm explicitly release long-lived monitor-service event subscriptions and manually-owned UI resources during teardown, including direct-dispose and future form-recreation paths.

## Root cause

MainForm subscribed to `ChatGptMonitorService.Activity`, `HistoryChanged` and `RunningStateChanged` using anonymous lambdas. Those delegates could not be removed later and the monitor service could therefore retain callbacks targeting a torn-down MainForm. MainForm also owns a manually-created `ToolTip`, while UI-007's status font cleanup sat in `OnFormClosing` instead of the form's resource ownership boundary.

## Delivered implementation

1. Replaced the three anonymous monitor-service subscriptions with named handlers.
2. Each named subscription has a matching unsubscribe in `Dispose(bool)`.
3. Named handlers retain the existing `Ui(...)` shutdown/disposal guard before touching controls.
4. MainForm-owned `ToolTip` and Runtime-status `Font` are disposed exactly once through `Dispose(bool)`.
5. `OnFormClosing` remains responsible only for graceful async shutdown sequencing, not resource disposal.
6. Existing activity, stored-history and running-state refresh behavior is preserved.
7. Regression coverage locks named subscribe/unsubscribe symmetry and the explicit once-only resource lifecycle.
8. No monitoring semantics, CDP behavior, recovery, delivery, SQLite schema, setup or release-publisher behavior changed.

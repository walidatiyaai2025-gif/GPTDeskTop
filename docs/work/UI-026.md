# UI-026 — Single-owner 44px dashboard status header

## Goal
Remove the final competing dashboard-header layout pass and return additional fixed vertical space to the primary operator workspace without losing live status visibility.

## Implementation
- `CompactDashboardHeaderLayout` is the only physical sizing owner for the primary dashboard header.
- The legacy `CompactOperatorHeaderExperience` remains only as a compatibility delegate to that owner; it no longer schedules a delayed `BeginInvoke`, sets a 58px row, or sizes metric chips independently.
- The final dashboard row is **44 logical px** at 96 DPI and scales from `DeviceDpi`.
- Root/header vertical padding and bottom margin are reduced to match the shorter status strip.
- The four existing metric chip panels remain present at **108 x 30 logical px**.
- Each existing caption/value Label pair is re-hosted inside its same chip as a one-row, two-column presentation. The original Label instances are reused, so MainForm's live metric references and updates remain untouched.
- Long captions may ellipsize visually; the full caption remains available through accessibility metadata and tooltip text.
- The dashboard purpose subtitle stays removed from visual layout while remaining available through accessibility/tooltips.

## Acceptance
- No legacy pass can restore a 58px dashboard row after the final owner runs.
- Running, Monitors, Conversation tabs, and Chrome window remain visible and use their original bound Label instances.
- Header and metric dimensions remain DPI-aware.
- No monitor lifecycle, recovery, persistence, database, or Chrome behavior changes.
- Merge only after the established CI gates are green.

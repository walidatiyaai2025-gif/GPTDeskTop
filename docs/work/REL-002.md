# REL-002 — Stable Build Identity Inside the Running Application

Issue: #99

Implementation branch: `agent/rel-002-build-identity`

Status: **DONE / VERIFIED / MERGED**

## Objective

Make every automation-published stable executable self-identifying after it is copied away from the repository. The semantic product version remains `1.8.0`; the stable build identity identifies the exact verified `main` source build.

## Delivered contract

1. `Update Last release` derives an eight-character build ID from the exact verified source SHA.
2. The stable publish stamps `InformationalVersion` as `1.8.0+stable.<build-id>` while preserving Assembly/File version `1.8.0.0`.
3. The publisher verifies the generated EXE actually contains the expected stable build ID before it can replace `Last release`.
4. `ApplicationBuildIdentity` reads and validates the stable metadata at runtime.
5. Local/developer builds without a `+stable.<build-id>` stamp keep the normal `v1.8.0` presentation.
6. Stable builds expose the short source identity in the MainForm window title, for example `GPTDeskTop v1.8.0 • stable abcdef12`.
7. `RELEASE.txt` records the same stable build ID and embedded informational version next to the full source commit and SHA-256.
8. Existing 8/8 same-SHA validation, compression, stale-main protection, size safety and `[skip ci]` recursion protection remain unchanged.

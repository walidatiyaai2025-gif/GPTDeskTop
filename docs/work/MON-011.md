## Objective

Release per-monitor lifecycle synchronization resources after the last Start/Stop/Delete transition for a Monitor ID reaches quiescence, without weakening serialization for registered holders or waiters.

## Root cause

`ChatGptMonitorService` retained one `SemaphoreSlim` forever in `_lifecycleGates` for every Monitor ID ever touched during the process lifetime. Because Monitor IDs are persistent/autoincrementing, repeated create/delete churn caused the dictionary and semaphore set to grow monotonically.

Simply removing a gate after `Release()` is unsafe because another operation may already have obtained the same semaphore reference and be waiting. Cleanup therefore requires explicit reference accounting that includes both the current holder and every waiter before they block.

## Implemented contract

1. `_lifecycleGates` stores `LifecycleGateEntry` objects rather than raw semaphores.
2. `AcquireLifecycleGateAsync` creates/finds the entry and increments `ReferenceCount` under `_sync` before `WaitAsync`.
3. Start, Stop and Delete hold an `IDisposable` lifecycle lease for the whole transition.
4. Lease disposal releases the semaphore exactly once via an `Interlocked` guard.
5. Reference count is decremented under `_sync` after release.
6. The dictionary entry is removed only when the count reaches zero and the dictionary still points to that exact entry.
7. The semaphore is disposed only after successful removal at zero references.
8. A waiter registered before release therefore keeps the entry alive; a transition arriving after true quiescence safely creates a fresh entry.
9. Different Monitor IDs remain independently serialized.
10. MON-009 runtime cleanup ownership and MON-010 Delete/Start serialization remain unchanged.

## Regression coverage

`ChatMonitorLifecycleGateReclamationTests.cs` verifies:

- a same-ID waiter increments the reference count before waiting and keeps the gate alive;
- releasing the first holder allows the waiter to acquire the same entry;
- the final lease removes the dictionary entry;
- different Monitor IDs acquire independently and both entries are reclaimed;
- repeated completed Stop transitions for historical IDs leave zero retained gate entries;
- source ordering requires reference registration before `WaitAsync` and identity-guarded removal at zero references.

Existing MON-008 and MON-010 source-contract tests were updated to assert the lease-based lifecycle boundary without weakening their original serialization guarantees.

# UI-006 — Home status font resource lifecycle

Issue: #105

Implementation branch: `agent/ui-006-status-font-cache`

Status: **IN PROGRESS — implementation complete, CI verification pending**

## Objective

Keep the long-running Saved Monitor status presentation visually identical while removing per-formatting GDI font allocation from the DataGridView hot path.

## Root cause

`HomeMetricsService.OnStatusCellFormatting` previously executed `new Font(grid.Font, presentation.FontStyle)` every time a Running/Stopped status cell was formatted. DataGridView formatting can occur repeatedly because of repaint, scrolling, invalidation and runtime state changes, so the UI created short-lived GDI-backed Font objects continuously during normal operation.

## Implementation

- Added an owned status-font cache to `HomeMetricsService`.
- Cache identity includes the effective base font family, size, graphics unit, GDI charset, vertical-font flag and requested `FontStyle`.
- Running/Stopped status formatting now calls `GetOrCreateStatusFont(...)` instead of allocating a font per callback.
- Existing status text, colors and bold styling are unchanged.
- Every cached Font is disposed and the cache is cleared when `HomeMetricsService.Dispose()` runs.
- Added `HomeMetricsFontResourceRegressionTests` to lock the no-per-paint-allocation and disposal contract.

## Compatibility

No monitor worker, ChatGPT/CDP, recovery, delivery, conversation ownership, SQLite schema, configuration backup, setup or release-publisher behavior changes.

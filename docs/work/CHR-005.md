# CHR-005 — Hidden Open Conversations enumeration QA

## Status
IN PROGRESS — implementation complete on branch; awaiting PR CI.

## Goal
Prove the user-visible Open Conversations target list remains enumerable for the entire period that monitor Chrome is hidden, not only that an already-bound DevTools session can still read page state.

## Implementation
- `HiddenChromeProcessProbe` now calls `ChromeDevToolsService.GetTabsAsync()` on every hidden-cycle.
- The probe records successful tab enumerations, matching target enumerations, enumeration failures, and the final visible target count.
- A newly enumerated matching tab replaces the probe's prior tab binding, mirroring the live target discovery path used by the application.
- `QA Hidden Chrome CDP` now fails if the expected target disappears from hidden enumeration, if enumeration becomes too unreliable, or if the final target list is empty.
- `HiddenChromeContinuityRegressionTests` locks the new probe/workflow contract.

## Safety invariants
- Production Hide/Show behavior is unchanged by this task.
- The probe still uses a deterministic local HTML page and an isolated Chrome profile.
- No ChatGPT messages are sent by the QA probe.
- Existing hidden CDP polling thresholds remain enforced.

## Verification required
- Runtime test suite green.
- `QA Hidden Chrome CDP` green on Windows/Chrome.
- All established PR workflows green before merge.

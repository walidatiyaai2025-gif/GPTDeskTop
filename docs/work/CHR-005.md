# CHR-005 — Hidden Open Conversations enumeration QA

## Status
VERIFIED — merged via PR #221 as stable source `62dc7e940a0f8e0b6eff95c988bea94e3fc6818c`; 8/8 required workflows passed and stable build ID `62dc7e94` was published.

## Goal
Prove the user-visible Open Conversations target list remains enumerable for the entire period that monitor Chrome is hidden, not only that an already-bound DevTools session can still read page state.

## Implementation
- `HiddenChromeProcessProbe` calls `ChromeDevToolsService.GetTabsAsync()` on every hidden-cycle.
- The probe records successful tab enumerations, matching target enumerations, enumeration failures, and the final visible target count.
- A newly enumerated matching tab replaces the probe's prior tab binding, mirroring the live target discovery path used by the application.
- `QA Hidden Chrome CDP` fails if the expected target disappears from hidden enumeration, if enumeration becomes too unreliable, or if the final target list is empty.
- `HiddenChromeContinuityRegressionTests` locks the probe/workflow contract.

## Safety invariants
- Production Hide/Show behavior was unchanged by CHR-005.
- The probe uses a deterministic local HTML page and an isolated Chrome profile.
- No ChatGPT messages are sent by the QA probe.
- Existing hidden CDP polling thresholds remain enforced.

# CHR-004 — Hidden Chrome runtime continuity

## Status
VERIFIED — merged via PR #219; stable source build `50639d53d31f03663357f738b6c2dffad3551158` passed all eight required workflows and was published to `Last release/GPTDeskTop.exe`.

## Reported symptom
After the operator hides the monitor Chrome window, monitoring can stop making progress and the main-window Open ChatGPT Conversations list can lose its visible conversation tabs. Exception logs can show `ChromeDevToolsService.CloseMonitorBrowser` with a WebSocket/ObjectDisposed disconnect while `Browser.close` is executing.

## Root cause boundary
The hidden-window action and running-monitor auto-recovery were able to interact destructively:
- Hide changed the Chrome window to `minimized` over CDP while monitor page sessions were actively polling, then applied native `SW_HIDE`.
- Four consecutive recoverable CDP failures could immediately escalate to `CloseAllMonitorTabsAsync` and a full browser relaunch.
- The expected socket teardown produced by `Browser.close` was persisted as an exception even though tearing down the socket is a normal close outcome.

## Implementation
- Prefer native `SW_HIDE` / `SW_SHOW` for ordinary Hide/Show; use CDP window-state changes only as a no-native-handle fallback.
- Launch monitor Chrome with background/occlusion throttling disabled so hidden pages remain active for monitoring.
- Require an additional bounded 8 x 250ms DevTools endpoint grace window before destructive browser restart.
- Reuse/recreate the exact saved conversation if the endpoint returns during the grace window.
- Preserve the hidden preference if a sustained outage genuinely requires browser restart.
- Suppress only the expected WebSocket/ObjectDisposed disconnect caused by `Browser.close`; unexpected close failures remain logged.

## Safety invariants
- Stable conversation identity remains authoritative.
- No chat message is sent by browser transport recovery.
- The existing monitor recovery threshold remains 4 consecutive transport failures.
- A genuinely sustained browser/CDP outage can still restart the dedicated monitor browser.
- Existing shutdown process cleanup remains intact.

# UI-022 — Stored History on-demand workspace

## Goal
Keep the primary GPTDeskTop operator surface focused on open ChatGPT conversations and active/saved monitors. Stored History must not reserve permanent vertical space on the main window.

## Implementation
- `OperatorWorkspaceV2Experience` removes the existing `HistoryWorkspaceControl` from `MainForm` after the compact Commands menu is available.
- The existing **Live Monitor & History** window now contains two tabs: **Live Activity** and **Stored History**.
- The original `HistoryWorkspaceControl` instance is re-hosted; search, filters, refresh, copy and CSV export remain the same controls and database path.
- Re-hosting exposes the existing history body without writing `IsExpanded`, so the move itself does not mutate the persisted expansion setting.
- `ExpandableWorkspaceLayout.UseHostManagedHeight` explicitly yields fixed 56/330px height ownership when an expandable workspace is moved into a full-height tab host. Existing resize/DPI callbacks remain registered but no longer fight `DockStyle.Fill`.
- The old History expand/collapse button is hidden in the full-height tab because the tab itself is the on-demand visibility boundary.

## Acceptance
- No permanent Stored History strip remains on the main workspace.
- **Live Monitor & History** exposes both **Live Activity** and **Stored History** tabs.
- Stored History fills its tab and retains existing operator actions.
- Re-hosting does not write the persisted expansion state.
- Host-managed controls are exempt from fixed dashboard heights across resize/DPI events.
- Runtime/business/database behavior is unchanged.
- Merge only after the established CI gates are green.

## Objective

Make the Settings UI match MON-007's error-driven runtime contract without breaking schema 1.0 configuration backup compatibility.

## Implementation

- Removed the active `No-response refresh` numeric control from Settings > Monitoring.
- Removed its obsolete accessibility copy that promised a timed tab refresh.
- Removed `NoResponseRefreshSeconds` from ordinary Settings load/save behavior, so a normal Settings save does not rewrite the legacy value.
- Added clear operator copy: slow, thinking, streaming, unchanged or temporarily empty responses wait indefinitely; elapsed time alone never refreshes or recovers a healthy chat.
- Preserved `NoResponseRefreshSeconds` in `ConfigurationBackupService.AllowedSettingKeys` and preserved schema `1.0`.
- Production `ChatGptMonitorService` remains independent of the legacy key.

## Compatibility

Existing databases keep the legacy setting untouched. Existing schema 1.0 backups can still export/import the key. No data migration, backup schema bump, recovery change or monitor runtime change is introduced.

## Regression coverage

`RetiredNoResponseSettingUiTests.cs` verifies:

- no active elapsed-time refresh control or stale promise remains in Settings;
- ordinary Settings save does not write `NoResponseRefreshSeconds`;
- schema 1.0 backup allowlist still includes the legacy key;
- production monitor still does not consume the legacy key.

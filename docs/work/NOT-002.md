## Objective

Apply notification duration and sound changes to the running tray notification service immediately after a successful Settings save or configuration import from the main window, without restarting GPTDeskTop or monitor workers.

## Root cause

`TrayNotificationService` caches `NotificationDurationSeconds`, `NotificationSoundEnabled`, and `NotificationSoundType`. It already reloaded those values after the tray menu's own Settings dialog, but `MainForm` had no narrow path to request the same reload after its separate Settings dialog returned success.

## Implementation contract

1. `TrayNotificationService.ReloadSettingsAsync()` is the only public notification-cache refresh boundary.
2. `MainForm` accepts an optional `Func<Task>` reload callback so it remains decoupled from tray internals.
3. `Program` wires `notifications.ReloadSettingsAsync` into `MainForm`.
4. The callback is invoked only after `SettingsForm.ShowDialog(...)` returns `DialogResult.OK`.
5. Cancelled or failed Settings operations do not invoke the callback.
6. A callback failure is logged and surfaced in Live Activity, but does not roll back already-committed settings or prevent the main window from refreshing persisted monitor/default presentation.
7. The tray menu's existing Settings flow remains functional and continues to reload the same cache boundary.
8. No monitor restart or application restart is required for notification-only changes.

# CHR-006 — Physical native Hide/Show QA

## Status
IN PROGRESS — implementation complete on branch; awaiting PR CI.

## Goal
Prove the exact production native owned-window visibility path keeps monitoring and Open Conversations alive while Chrome is physically hidden.

## Gap closed
CHR-004 changed production Hide/Show to prefer native `SW_HIDE` / `SW_SHOW`, with CDP minimize/normal only as a fallback. CHR-005 proved target enumeration stays alive while hidden, but the physical probe launched Chrome outside `ChromeDevToolsService`, so the probe could validate the fallback path instead of the owned native-window path.

## Implementation
- The deterministic physical probe adopts its isolated Chrome process as the `ChromeDevToolsService` owned monitor process for QA only.
- The probe waits for the real Chrome `MainWindowHandle` and records native visibility before Hide, after Hide, and after Show.
- `QA Hidden Chrome CDP` now requires the physical transition `visible -> hidden -> visible`.
- Existing hidden `GetTabsAsync()` enumeration and `GetChatStateAsync()` polling remain mandatory throughout the hidden interval.
- Source-contract regression coverage locks the physical native-window receipt.

## Safety invariants
- No production Hide/Show implementation is changed by CHR-006.
- CDP minimize/normal remains available when no native handle can be resolved.
- The QA probe uses a deterministic local page and isolated Chrome profile.
- No ChatGPT messages are sent by the probe.

- Runtime tests green.
- Physical `QA Hidden Chrome CDP` green on Windows/Chrome.
- All eight established PR workflows green before merge.

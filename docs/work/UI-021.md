# UI-021 — Compact dashboard status header

## Status
IN PROGRESS — implementation complete on branch; awaiting PR CI.

## Goal
Return the remaining fixed header space to the operational workspace so Live Activity stays visible without removing any live status metric.

## Root cause
The command rows and expandable Development Plan / Runtime Health areas are compact, but `MainForm` still creates an 82px hero header and `MainDashboardExperience` increases header/chip padding with a 48px minimum metric-chip height. That left a large fixed block above the workspace.

## Implementation
- Added `CompactDashboardHeaderLayout` as the final main-header layout owner.
- It deterministically applies `MainDashboardExperience` first, then compacts the final layout so makeover ordering cannot re-expand the header.
- Final header row is 56 logical px with reduced root/header vertical padding.
- The visual subtitle row is collapsed to zero and hidden; the same purpose text remains on header/title accessibility metadata and tooltips.
- All four existing live metric chips remain present and use the same label/value controls and bindings.
- Metric chips are compacted to 108 x 40 logical px and remain non-wrapping.
- DPI changes reapply the compact physical dimensions from logical constants.
- Added source-contract regression tests covering final ownership, accessibility, all four metrics and reclaimed padding.

## Safety invariants
- No browser, monitor, delivery, recovery, persistence or metric-binding behavior changes.
- The four existing metric values remain the original controls updated by `MainForm`.
- `MainDashboardExperience` still owns colors/visual polish; UI-021 owns only the final compact header geometry.
- Compact layout is applied only to `MainForm`.

- All eight established PR workflows green before merge.

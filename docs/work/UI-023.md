# UI-023 — Runtime Health on-demand workspace

## Goal
Reserve the primary GPTDeskTop window for the operational conversation/monitor workspace. Runtime Health and Support Diagnostics should remain available without occupying permanent top-level height.

## Implementation
- `OperatorWorkspaceV2Experience` waits until `CompactTopCommandMenuExperience` has harvested existing Runtime Health buttons, preserving those controls as the command behavior source.
- The existing `RuntimeHealthControl` and `SupportDiagnosticsControl` instances are removed from `MainForm` and re-hosted in a **Runtime Health** tab inside **Live Monitor & History**.
- The on-demand window now contains **Live Activity**, **Stored History**, and **Runtime Health** tabs.
- `ExpandableWorkspaceLayout.UseHostManagedHeight(runtimeHealth)` prevents the old dashboard fixed-height owner from fighting the re-hosted control.
- Re-hosting does not assign `runtimeHealth.IsExpanded` and does not change `supportDiagnostics.Visible`, so the persisted Runtime Health expansion preference remains authoritative.
- Repair, retry-recovery, refresh, health metrics and support-bundle behavior continue to use the same control instances and services.

## Acceptance
- No Runtime Health or Support Diagnostics strip remains on the main operator surface.
- Runtime Health and Support Diagnostics are available from the on-demand window.
- Commands-menu Runtime Health actions continue to invoke the original buttons.
- Existing persisted expansion state is not mutated simply by re-hosting.
- Existing runtime/database/monitor behavior is unchanged.
- Merge only after the established CI gates are green.
